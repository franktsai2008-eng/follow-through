# Follow-Through v3 — meeting → strategy talk → draft → human edit → send → learn (Frank's flow, 2026-09-11 15:55)

Frank's call: the "two agents talking" framing confuses people. The product is: take the details of a meeting, work out the follow-up
reply strategy WITH the person first, then produce a draft, the person makes the final edits, and every place a person touched
becomes learning (a lesson) and long-term memory. Sponsor tools sit inside that loop. Frank records the demo video himself.

## Flow (one case = one meeting)
1. MEETING IN — paste meeting notes/transcript + your company, their company, your role, your authority limits, recipient.
2. DIGEST — the agent structures it: summary, decisions, commitments (who/what/when), open items, risks. You.com adds 1–2 lines of
   public context about the other company/product with source domains (live web data).
3. STRATEGY TALK — a CrewAI crew (strategist + skeptic) proposes 2–3 follow-up strategies; then the agent discusses with the person
   in a chat (asks at most one question per turn, adjusts). The person clicks LOCK when the approach is right.
4. DRAFT — the agent writes the follow-up email from the locked strategy + digest + recalled lessons.
5. HUMAN EDIT + SEND — the person edits subject/body/recipient, presses Send; One sends it through Gmail (allowlist).
6. LEARN — every human-touched place is diffed against what the agent produced: chat corrections, the edit of the draft, a rejected
   strategy. Each becomes one lesson (≤40 words) → app/lessons.md (source of truth) + One memory. Next case starts with RECALLED.
7. HARNESS — a deterministic script computes, per case, how much of the agent's draft the person had to change (edit ratio) and the
   trend across cases; it replays in a Daytona sandbox (records only). Learning target: the person edits less over time.

## Sponsor tools, one real step each
- You.com Search API → public context lines on the digest (POST https://ydc-index.io/v1/search, query written from the notes).
- CrewAI → strategy options crew (2 agents, sequential: strategist drafts 3 options, skeptic marks risks and picks a recommended one).
- One → sends the final email; `one mem add` mirrors every lesson; `one mem search` count shown as Recalled.
- Daytona → replays the edit-ratio harness over all cases in a sandbox neither side controls.

## Files
- app.py (rewrite of the request layer; keep helpers: load_env, call_claude, one_probe, one_send, one_mem_add/count, mirror_lesson, JID_RE, ALLOWED, rate limits, save/load).
  Cases persist in app/cases/<id>.json (gitignored). Keep the old two-agent endpoints OUT of the new app (the harness stays in the repo as research).
- crew_options_job.py (run with .venv/bin/python; CrewAI 2 agents; input JSON {digest, context, company_me, company_other, my_role, authority, lessons}; output the `options` object). Model via .crew_model file (opus) as today.
- harness_job.py (pure python; input: a JSON list of {id, draft_body, final_body, created_at}; prints a table: case, chars changed, edit ratio, trend; exit 0). daytona_replay.py reused with the new payload.
- app/index.html (single file, same space-black tokens as v2; stepper across the top; left rail = meeting input; center = digest → strategy chat → draft editor; right rail = context, options + skeptic note, Recalled/Learned, harness card, past cases).
- README.md, REPORT-200.md rewritten to the new story (docs agent).

## UI rules (unchanged from v2)
Pure black, white text, hairlines, Inter + JetBrains Mono, white pill primary buttons, no shadows/gradients/purple/orange/lime/emoji, motion only transform/opacity, prefers-reduced-motion fallback, full HTML escaper, no horizontal scroll, one file ≤ 45 KB, Recalled and Learned visible above the fold on 1440×900 after a case is sent.
Empty state: three lines (paste what happened in the meeting → agree the follow-up strategy with the agent → edit the draft, send, it learns from your edits).

## Definition of done
- A case goes notes → digest (with You.com lines) → crew options → 2 chat turns → lock → draft → edit → send (real Gmail id shown) → Learned lines shown; next case shows Recalled with those lessons.
- Harness replay runs in Daytona (key present) and prints the edit-ratio trend.
- /status all green; impeccable-detect clean; no secrets to the browser; allowlist + rate limit + id validation kept.
